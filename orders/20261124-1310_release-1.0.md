## Order 1
Target files: `scripts/set-exe-lang.mjs` (new), `src-tauri/tauri.conf.json`

### Background
tauri-build writes the VERSIONINFO resource via tauri-winres with `language: 0`. In the compiled exe this appears as:
- the StringFileInfo child block key `"000004b0"` (UTF-16LE string), and
- the VarFileInfo `Translation` value: two u16 little-endian values `0x0000, 0x04b0` immediately following the UTF-16LE key `"Translation\0"` (plus padding to 4-byte alignment) inside the `Var` struct.
Explorer's Details tab "언어" reads the Translation value. Tauri 2 supports `build.beforeBundleCommand`, which runs after the Rust binary is compiled and before NSIS bundling.

### Changes
1. New `scripts/set-exe-lang.mjs` (Node, no dependencies):
   - Path argument default `src-tauri/target/release/popsearch.exe` (resolve relative to the repo root = parent of `scripts/`).
   - Read the file as a Buffer. Find the VS_VERSION_INFO resource by locating the UTF-16LE string `VS_VERSION_INFO`; work only inside that resource (bounded by its wLength u16 at the struct start, i.e. 6 bytes before the key; verify sanity).
   - Inside it: replace the UTF-16LE `000004b0` StringTable key with `041204b0` (same length), and find the UTF-16LE `Translation` key, skip to its value (after the null terminator, align to 4 bytes from the struct start of the resource data), check the value is `00 00 b0 04`, and write `12 04 b0 04`.
   - If already Korean (`041204b0` and `12 04 b0 04`), print "already ko-KR" and exit 0. If the expected patterns are not found exactly once, print a clear error and exit 1 (do not write a partially patched file).
   - Write the file back in place; print what was changed.
2. `src-tauri/tauri.conf.json` `build` section: add `"beforeBundleCommand": "node scripts/set-exe-lang.mjs"`. Check the working directory Tauri uses for this command (it runs from the project root where `package.json` is, same as beforeBuildCommand); make the script path robust either way by resolving relative to the script file.
